# MultiApp

Мультифункциональная социальная платформа: лента, чаты, музыка, видео, изображения, новости и поиск — всё в одном приложении с единым аккаунтом.

## Стек

Frontend: React 18, Vite, Tailwind CSS, React Router, Zustand, Axios.

Backend: Go, Fiber, WebSocket, pgx, JWT, bcrypt.

База данных: PostgreSQL.

## Что умеет

Пользователи могут регистрироваться, входить, выходить, редактировать профиль, подписываться на других и писать им в чат.

В ленте можно создавать посты, лайкать и комментировать.

В мессенджере сообщения приходят в реальном времени, есть индикатор «печатает…».

Музыка играет через глобальный плеер, который не останавливается при переходе между разделами.

Видео можно смотреть, лайкать, комментировать и публиковать.

Изображения собираются в Pinterest-ленту, можно создавать доски и сохранять в них картинки.

Новости вынесены в отдельную вкладку с фильтром по категориям.

Есть общий поиск по людям, постам, видео, музыке, изображениям и новостям.

## Структура

В папке `backend` находится сервер на Go: точка входа в `cmd/server`, бизнес-логика в `internal`, SQL-миграции в `migrations`.

В папке `frontend` находится клиент на React: страницы в `src/pages`, стор в `src/store`, axios-клиент в `src/api`, общий layout в `src/layouts`.

В корне лежат скрипты `start.ps1` и `stop.ps1` для запуска и остановки проекта.

## Требования

Нужно установить Go 1.22 или выше, Node.js 20 или выше, PostgreSQL 16 или выше.

Проверить установку можно командами:

    go version
    node -v
    psql --version

## Установка

Откройте PowerShell и создайте пользователя и базу данных PostgreSQL. Замените пароль `MyPass123!` на свой пароль от пользователя postgres.

    $env:PGPASSWORD = "MyPass123!"
    psql -h localhost -U postgres -c "CREATE USER multiapp WITH PASSWORD 'multiapp';"
    psql -h localhost -U postgres -c "CREATE DATABASE multiapp OWNER multiapp;"
    psql -h localhost -U postgres -c "GRANT ALL PRIVILEGES ON DATABASE multiapp TO multiapp;"

Если пользователь или база уже есть, команды скажут «already exists» — это нормально.

Создайте файл `backend/.env` со следующим содержимым:

    PORT=8080
    DATABASE_URL=postgres://multiapp:multiapp@localhost:5432/multiapp?sslmode=disable
    JWT_SECRET=change_me_super_secret
    UPLOAD_DIR=./uploads
    PUBLIC_URL=http://localhost:8080

Разрешите запуск PowerShell-скриптов. Откройте PowerShell от имени администратора и выполните:

    Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned

На вопрос ответьте Y.

## Запуск

Откройте PowerShell в папке проекта и запустите:

    .\start.ps1

Скрипт проверит наличие Go, Node.js и PostgreSQL, создаст базу данных, установит зависимости, запустит backend на порту 8080 и frontend на порту 5173, и откроет браузер.

При первом запуске скрипт спросит пароль от пользователя postgres — введите тот, что задавали при установке PostgreSQL.

## Остановка

Чтобы остановить проект, выполните:

    .\stop.ps1

Скрипт найдёт процессы на портах 8080 и 5173 и завершит их.

## Тестовые аккаунты

Первый: логин `A`, пароль `123456`, email `s@s.s`.

Второй: логин `B`, пароль `123456`, email `a@a.a`.

Зайти можно на странице входа, введя логин и пароль.

## Как проверить чат между двумя аккаунтами

Зайдите как A. Найдите через поиск пользователя B и откройте его профиль. Нажмите «Написать» — откроется чат. Отправьте сообщение.

Нажмите «Выйти» и зайдите как B. Откройте раздел «Сообщения» — увидите диалог с A. Ответьте.

Снова зайдите как A — увидите ответ.

## Переменные окружения

`backend/.env` содержит пять переменных.

`PORT` — порт backend, по умолчанию 8080.

`DATABASE_URL` — строка подключения к PostgreSQL.

`JWT_SECRET` — секретный ключ для подписи токенов.

`UPLOAD_DIR` — папка для загружаемых файлов.

`PUBLIC_URL` — публичный адрес backend.

## Основные API-эндпоинты

Регистрация: POST `/api/auth/register`.

Вход: POST `/api/auth/login`.

Обновление токена: POST `/api/auth/refresh`.

Текущий пользователь: GET `/api/me`.

Редактирование профиля: PATCH `/api/me`.

Лента: GET `/api/posts`.

Создать пост: POST `/api/posts`.

Лайк поста: POST `/api/posts/:id/like`.

Список чатов: GET `/api/chats`.

Создать чат с пользователем: POST `/api/chats/with/:userId`.

Сообщения чата: GET `/api/chats/:id/messages`.

Отправить сообщение: POST `/api/chats/:id/messages`.

Музыка: GET `/api/tracks`.

Видео: GET `/api/videos`.

Опубликовать видео: POST `/api/videos`.

Изображения: GET `/api/images`.

Доски: GET `/api/boards`.

Новости: GET `/api/news`.

Поиск: GET `/api/search?q=запрос`.

WebSocket: `/ws?token=<access_token>`.

Все защищённые эндпоинты требуют заголовок `Authorization: Bearer <access_token>`.

## Особенности

Access-токен живёт 15 минут, refresh-токен 30 дней. Обновление access-токена происходит автоматически.

WebSocket переподключается при разрывах соединения. В логе backend при перезагрузке страницы вы увидите строки вида `ws closed: 1001` — это нормально, не ошибка.

Все вкладки на `localhost:5173` используют один `localStorage`. Для параллельного входа под двумя аккаунтами откройте второе окно в инкогнито.

Миграции базы данных применяются автоматически при старте backend.

## Возможные проблемы

Если команда `go` не найдена — установите Go и добавьте его в PATH.

Если `psql` не найдена — добавьте папку `C:\Program Files\PostgreSQL\18\bin` в PATH.

Если пароль postgres не подходит — сбросьте его через файл `pg_hba.conf`, заменив `scram-sha-256` на `trust`, перезапустите службу PostgreSQL, зайдите без пароля и выполните `ALTER USER postgres PASSWORD 'новый';`.

Если порт 8080 или 5173 занят — запустите `.\stop.ps1` и попробуйте снова.

Если база данных не существует — создайте её вручную командами из раздела «Установка».

Если браузер показывает чёрный экран — откройте DevTools (Ctrl + Shift + I) и посмотрите ошибки в Console.

Если разделы «Музыка», «Видео» или «Новости» пусты — в базе нет данных, добавьте их через интерфейс.
